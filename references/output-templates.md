# Output & Reporting Templates for code-unclutter

エージェントがユーザーに診断結果・リファクタリング計画・完了サマリーを報告する際の標準テンプレート集。

---

## テンプレート1：【事前診断レポート】（Scan / Dry-Run時）

```markdown
# [CLEAN] code-unclutter 診断レポート

対象: `[ファイルパス / モジュールパス]`
検出された臭いの総数: `[N件]`

### [P1] Phase 1: まず直すべき最優先項目 (Quick-Wins)
- **[ファイル:行番号]** `[ルールID]`: [具体的な問題点と改善案]
- **[ファイル:行番号]** `[ルールID]`: [具体的な問題点と改善案]

### [P2] Phase 2: ロジック整理候補
- **[ファイル:行番号]** `[ルールID]`: [関数の肥大化やCQS違反の指摘]

### [GUARD] 安全確認
- 既存テストスイート: `[検出済 (例: pytest) / 未検出]`
- 推奨アクション: `[Phase 1 の自動適用 / 仕様化テストの先行作成]`
```

---

## テンプレート2：【リファクタリング完了サマリー】（実行後）

```markdown
# [OK] code-unclutter リファクタリング完了報告

## [METRICS] 実施概要
- **対象スコープ**: `[ファイル / モジュール / Git差分]`
- **適用フェーズ**: `[Phase 1 Quick-Wins / Phase 2 Logic]`
- **変更ファイル数**: `[Nファイル]`
- **テスト検証結果**: `[全テスト通過 (グリーン) / 自動コミット完了]`

## [TOOL] 主な改善内容
1. **[No.51 ガード節]**: `[関数名]` の3重ネストを早期リターンで平坦化（インデント深度: 3 -> 1）
2. **[No.05 マジックナンバー]**: `[86400]` を定数 `SECONDS_PER_DAY` に置換
3. **[No.71 例外処理]**: 空の `catch` ブロックに構造化エラーログを追加
4. **[No.08 デッドコード]**: 未使用関数 `[funcName]` を削除

## [SCAN] 差分ハイライト (抜粋)
```[言語]
// 改善された主要箇所のコードスニペット
```

## [TIP] 次のステップ（任意）
- さらなる関数の抽出（Phase 2）を実施する場合は、`unclutter --mode purify` をご指示ください。
```
